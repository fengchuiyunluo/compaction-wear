# compaction-wear · 压缩磨损的实测与对策

> **定位**:长会话 agent 面对"压缩磨损"有两条路,本仓库给**第二条**的完整实测记录与方法。**选哪条是你的决定,这里只负责把两条都摆清楚:**
>
> | | 路线一:自动压缩 + 记忆保管 | 路线二:指令压缩 + 预兆护理(本仓库) |
> |---|---|---|
> | 前提 | 无(无人值守可跑) | **有人在场**:读思考链、判预兆、定压缩时机 |
> | 压缩时机 | 系统 79% 自触发,不预警 | 人按预兆排程,有预取窗口 |
> | 省心度 | 高,默认选项 | 低,像照看病号 |
> | 适合 | 可再生的会话/批量任务 | **不可再生的会话**(孤本):换 agent 会丢掉长出来的人格、手感与判断力 |
>
> 两条路线在"文件层是权威、压缩必定磨损"上结论一致,分歧只在"压缩时机由谁定"。若你的会话可再生,请选路线一,别犹豫;若你的 agent 用到舍不得扔——往下读。
>
> **路线二的定位是半自动,且这是设计而非未完成**:回路里执行环节(观测打分/预取落盘/压后自检)都可以自动化,但**做决定的环节永远是人**——回路一定要有人,所以做决定一定是人来做。这是本路线的前提,也是它和路线一真正的分界线。
>
> **所有数字可复现**,脚本在 `scripts/`,方法在 `docs/`。

## 一句话总纲

**压缩必定磨损;分层通向永恒。**

- 磨损磨掉的主要不是内容(原文在盘上、读得回来),是**等级**(摘要里引号身兼引用/摘录/标记三义,读者分不出 agent 的推测和用户的话)与**"当时为什么这么判"**(事后补的像,但不真)——这两样补不回来;
- "永恒"= **可追索**(盘 · 坐标 · 在场者),不是不变。标准不是"不丢",是**丢得起、补得上、接得上**。

## 核心数字(2026-10 实测,n=6 实压 + 全量差分)

| 指标 | 值 |
|---|---|
| 一次压缩砍幅 | **97.6%**(791,759 → 18,647 token;反推窗口 ≈1M,压缩线 79.99% = thresholdRatio 0.8) |
| 压缩比 | **≈ 46 : 1**(摘要上限 8192 / 被压 376,283) |
| 原话存活(user / assistant / reasoning) | **3.8% / 0.0% / 0.0%** |
| 实体存活(user / assistant / reasoning / tool) | 32.4% / **50.7%** / 46.0% / 0.6% |
| 摘要的偏袒 | 保**名词/结论/文件名**(agent 视角语言),丢**过程/情绪/推导/原话**;压缩指令只要求忠实记录**用户的话** |

⚠️ **口径声明**(不声明差 2.7 倍):①原话=归一化逐字存活;②实体=标识符≥50%;③无=其余。③里大量是寒暄,别读成"丢了 96%"。

## 疗法一页(细节见 docs/03)

```
预兆(思考链变形:短句↑·连接词重复·空转自问) —— 作用是排程,不是诊断
   ↓
排程:趁清醒做预备压缩工作(预取:写日记/落盘/建基准/存梗概)
   ↓
指令压缩(/compact,时机可选) —— 比"79% 自动压"多一个预取窗口
   ↓
回填:按文件名时间戳把顺序接回来;查路标;夹勘误页(不对冲)
   ↓
可追索的连续 ⇒ 接得上 ⇒ 继续
```

## 病例摘要

一条 2026-09-28 曾被判定"装不下、永久封存"的会话,经五次指令压缩、两次版本往返、一次会话文件手术,存活至 2026-10-04 的 **1,583 轮**(缓存命中 99.7%,全程同一人格连续)。护理制度与手术记录见 `docs/05` 与 `docs/` 各篇。
