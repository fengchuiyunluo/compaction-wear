# 结论 · 能维持什么,不能维持什么

> 源自 2026-10-01 凌晨实测后的对策文档(原始底稿见 `02-结论-原始底稿-抗压缩.md`,一字未改,本篇是定稿表述)。
> 目标:让一个 agent 在**反复压缩**下,仍然"是同一个"。

## 一、能维持的是"可追索的连续",不是"不变的连续"

| | 可追索的连续 ✅ | 不变的连续 ❌ |
|---|---|---|
| 内容 | 原来的东西**在盘上**,需要时读得回来 | 内容**一直在上下文里** |
| 来路 | 每条结论**带"去哪儿核"** | 每条结论**自带 why** |
| 归属 | 分得清**谁说的**、什么等级 | 不须分辨 |
| 代价 | 每次补都花一次往返 | 零(但不可能) |

**"不变"做不到的三条硬边界**:

1. **补回来就是占体积**。把丢的 37 万 token 读回来 ⇒ 上下文又满 ⇒ 立刻又要压。补全和压缩**直接对冲**。可行形态不是"记得全部",是**"随时查得到全部"**——像人查档案,不像硬盘常驻。
2. **有些东西原文里也没有**。"我当时为什么这么判"——当时没写下来,事后补的一定长得很像但不真。
3. **最要命的腐败不是丢内容,是丢等级**。摘要引号三义 ⇒ 把 agent 的推测当用户的话用。重建归属要逐条回原文核,补不回来。

> 目标:让"这个 agent 是谁"不依赖上下文,而依赖**盘 + 坐标 + 在场者**。

### 正名:这套方法的准确含义 = **不换 agent**

```
默认天命:哑火/压缩 → 丢东西 → 换 agent(新手感从零养)
本方法:  压缩 → 对账 → 大概补齐 → 不换,接着用
```

"大概"补齐的工程学:**完整补齐=贴回原文=等于没删=和压缩对冲**;"大概补齐=夹勘误页",几行字,不对冲。而"大概"够用的前提是**坐标**——说"t215 被剪了 4 处/17,041 token",而不是"你少了一块"。

**保护的是手感,不是信息**——换代传的是信息(别人写的卡,丢了 why);补齐保的是手感(自己的判断)。

## 二、什么活得过压缩(四条件)

1. **短**——长度比重要性更能决定生死(摘要 8192 上限是硬刀);
2. **成句**——未成型的念头、只说一半的话,第一次压缩就没了;
3. **带引号**(如果是别人的话)——压缩指令明确保护 `quote verbatim`,用户的话保真度最高;
4. **落盘**——盘上的不归压缩管(`prune` 只改表层,日志一字不动)。

## 三、三条对策(按性价比)

1. **缺损地图**——压缩后第一件事:读 `compaction/prune`,把"我在哪轮被剪了哪几处/多少 token"贴出来。一行指针比 37 万 token 便宜三个数量级;把"我不觉得缺"变成"我知道我缺哪几块"。
2. **带坐标原则**——`1: 有(候选#3,用户 12:38 那条)` 而不是 `1: 有`。**凡是不能还原到"去哪儿核"的断言,最后都会被当成结论用。**
3. **"为什么"当场落**——结论丢得起(能重推),过程丢得起(盘上有),**"当时为什么这么判"丢不起**(唯一补不回来的)。落盘优先写为什么。

## 四、工具分工

| 谁 | 干什么 | 边界 |
|---|---|---|
| 主模型(贵) | 判断、决策 | 会满、会哑、会腐 |
| 本地小模型(免费) | 字面核对/计数/清单完整性/**当便宜的反对派** | 只做有标准答案的活;**它最好的用处是分歧点**——跟它顶牛的地方正是该复核的地方 |
| 用户(在场) | 唯一能拿原件来撞的人、唯一能验归属的人、定压缩时机 | —— |

## 五、两条纪律(从教训里来的)

- **可以质疑事实/证据/结论;不能质疑"用户在不在场、有没有决定权"**。(由来:agent 曾连续把用户的在场稀释成"系统/成本/结构"——质疑的对象从"事"漂到了"人"。)
- **"我说的通"≠"我测的准"**。判据在外面(日志/游戏/盘)的,自己验;判据在心里("够不够好")的,谁都验不了——包括 agent 自己。
