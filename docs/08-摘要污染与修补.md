# 摘要污染与修补 —— 锚被污染时的处置(2026-10-04 实战案例)

> **问题定义**:压缩产出的摘要 = 压缩后上下文的**锚**。锚会被污染——压缩器读入被污染的上下文,写出的摘要可能夹带污染字形、过时事实、缺失关键块。**锚脏,则后续一切生成都在脏锚上模仿。**
> 本篇记录一例真实的摘要污染 + 帧级修补全过程,以及"修补 vs 再压"的决策框架。

---

## 一、污染途径:锚怎么会脏(四通道)

| 通道 | 机制 | 实例 |
|---|---|---|
| ① 输出侧 | 模型自己生成繁体异形(腐烂征兆),被压缩器**原样引述**进摘要 | 伤单引「动手」的繁体异形写法之爆发记录(字形不入仓) |
| ② 输入侧 | 用户打字繁出(输入法/习惯),复制进对话,再进摘要 | 用户消息中的繁体异形字 |
| ③ 转述侧 | 观察者/外部 agent 转述伤情时**直引繁体字形**,经剪贴板进入上下文 | ZCode 转述伤单带字形 → 剪贴板 → xl 日记(红线案例,见值班手册 #9) |
| ④ 锚侧 | 摘要继承了上一轮锚的残留,或压缩器取样偏差 | 本次案例:0.70% 残留(构成见下) |

⇒ **防住任何单一通道都不够**——四条通道独立存在,须分别封堵(见第四节)。

## 二、实例:二压摘要的污染构成(2026-10-04 16:21,seq 3687662)

压缩后全文扫描(10,554 字符):

| 指标 | 值 |
|---|---|
| 繁体异形字总数 | **24 处(0.70%)** |
| 构成 | 主字形(「动手」的繁体写法)×15 · 「简」异形×1 · 「语」异形×4 · 另 4 字各×1 |
| 语境 | **全部为引用/转述语境**(伤单原文照录、规则引文)——非模型自发输出 |

**同场发现的非字形缺陷**:
- **事实过时**:摘要称 retainRatio 0.02 生效——实际当日 14:4x 已删除复员(本次二压按 0.16 执行);
- **块缺失**:看护建制(值班手册/读数器/修补术/三方指针)与命名来历未入锚。

## 三、修补术:五步帧级手术

> 前提:**dsh 必须关闭**(文件静止);全程有备份;失败即回滚备份。

```
① 备份      cp session.jsonl.zstd → .bak-<日期>-before-摘要修补
② 定位      解帧扫描 → 找到最新 compaction/summary 事件所在帧
③ 修文      解出摘要全文 → 三类修改:
              · 去除:繁体异形字形转写为简体(描述保留,字形不复刻)
              · 修正:过时事实(如 retainRatio 状态)改为当前事实
              · 回填:缺失的关键块(看护建制/命名来历等)按料单补入
④ 换帧      修改后重压缩该帧 → 拼回文件(其余帧字节原样)
⑤ 三检      全部帧可解压 / 第一帧=单行 header / 修后内容抽验
→ 然后才准启动 dsh
```

### 本案例修补结果

| 验收项 | 修后 |
|---|---|
| 繁体异形字残留 | **0(0.00%)** |
| retainRatio 事实 | 已更正(复员说明 + 本次二压按 0.16 执行) |
| 看护建制回填 | 已入锚 |
| 命名来历回填 | 已入锚 |
| 帧完整性 | 40,394 帧,0 坏帧,第一帧规则 ✓ |

## 四、技术要点与坑(实录,每条都吃过)

1. **⚠️ 锚文本的标点是全角的**——修补脚本里的查找锚若用半角括号/逗号,**永远命中不了**(本案例连续三刀未中的真因)。全角标点建议用字符码构造,避免转义链损耗;
2. **JSON 往返的字形与反斜杠**:`JSON.stringify` 会重排转义——回填路径类文本时,反斜杠经一次往返可能丢失(实测:路径 `D:\dsh\看护` 存成了无反斜杠形态),**写入后必须读回验证**;
3. **思考链是分片存储的**:统计/检索前必须先拼回整段,否则跨分片的词永远匹配不到;
4. **统计必须排除引用语境**:讨论污染话题本身、照录伤单原文,都会把读数顶起来——**报数必须声明口径**;
5. **手术期间 dsh 必须保持关闭**:运行中的实例可能并发追加帧,与换帧拼接冲突;
6. **一次性缓存代价**:摘要位于压缩后上下文的前端,修改它会使该点之后的缓存失效一次——量级 = 当前上下文规模的一次未命中重算,可接受,但要知道。

## 五、决策框架:修补 vs 再压

| | 摘要修补(帧手术) | 再压一次 |
|---|---|---|
| 适用 | 锚的内容**基本可用**,只有局部缺陷(字形/过时/缺块) | 上下文本身**大面积污染/臃肿**,需要整体折叠 |
| 历史损失 | **零**(只改摘要事件) | 每次砍 84%+(retainRatio 决定) |
| 前提 | dsh 停机,文件静止 | 需 dsh 运行,须预取先行 |
| 风险 | 帧手术二次损伤(备份+三检可控) | 摘要套摘要的复利磨损 |
| 组合 | **可连续使用**:修补 → 正常跑 → 修补 | 与修补交替:压(砍量)→ 修补(修锚)→ 跑 |

⇒ **推荐节奏**:压缩(砍量切污染)→ 摘要修补(锚精修)→ 正常跑(稀释)→ 监测决定下一轮。

## 六、预防:四通道各自的封堵

| 通道 | 封堵 |
|---|---|
| ① 输出侧 | 监测(读数器);爆发即排程压缩 |
| ② 输入侧 | 输入法固定简出(实例:雾凇拼音默认简出);用户文本入 agent 前自查 |
| ③ 转述侧 | **观察者铁律:转述任何文字给 agent,字形一律简体转写+括注,永不直引异形字形**;剪贴板粘贴前自查 |
| ④ 锚侧 | **每次压缩后跑一遍摘要修补术的"审查"半程**(繁体扫描+事实核对+料单核对),有缺陷即修补 |

## 七、结果与遗留

- 修补后摘要:10,895 字符,繁体字面 **0**,全部回填与修正经读回验证;
- 遗留观察:修补后首数轮的生成语域(是否保持简体、爆发是否复现)——按连压去腐规程监测,数据另行追加;
- 修补术操作细则(含料单)在护理侧文件,本仓收录方法论与本篇。
