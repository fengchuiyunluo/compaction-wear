# 实验报告 · 压缩磨损的测量(n=6)

> **问题**:系统压缩(或指令压缩)把长上下文压成摘要后,究竟丢了什么、丢多少?
> **为什么不能只看摘要**:摘要本来就"应该"比原文短。要测"磨损",必须拿**压缩前的完整原文**对**压缩后的摘要**做差分。
> **前提(官方设计)**:DSH 会话文件 `session.jsonl.zstd` 只追加、不改历史——`compaction/prune` 只改"喂进模型的表层",盘上日志一条不动(实测核验:4 条 shadowedSeqs 内容全部完整在盘)。**这个设计使磨损可测。**

---

## 一、方法(三层,互验)

### 第一层:盘上差分(全量,机械)

- 解会话文件:逐帧 zstd(魔数 `28 B5 2F FD`)→ 逐行 JSON → 取**压缩点之前**的全部记录;
- 对摘要做三档判定,四类记录分开统计:
  - **①原话** = 归一化(去空白)后逐字出现在摘要里(`摘要.includes(原文)`)
  - **②实体** = 原文的标识符(路径/文件名/数字/英文词/参数)≥50% 出现在摘要里
  - **③无** = 其余(⚠️ ③里大量是"继续/唉"类寒暄,本就不该进摘要——别读成"丢 96%")
- **全量不抽样**(脚本秒级);**口径必须随数声明**——剥不剥行内代码,同会话数字差 2.7 倍。

### 第二层:实压实验(n=6)

- 拿 **6 个实际的新 agent**,灌入实际档案,逐个手动触发压缩(指令压缩),压完即测;
- 灌入全是缓存未命中(1~2 元/百万),是本实验的主要成本;
- n=6 的意义:存活率从 n=1 的孤证变成**分布**。

### 第三层:人工点验(定性)

- 拿压缩前档案与压后摘要**当面点验**(人工读两边):
  - 单样本细点:382 token 里活 36 = **9.4%**,"十份活一份";
  - 定性结论只有人能给:摘要留**名词/结论/文件名**,丢**过程/情绪/明细/原文/推导**;**引号三义**(真引用/剪短摘录/普通标记,读的人分不出)。
- 脚本分不清"剪短的摘录"和"普通引号"——这一层机器替代不了。

## 二、结果

### 2.1 压缩参数与实测线(配方本地可查,不用猜)

| 项 | 值 |
|---|---|
| thresholdRatio | 0.8(默认) |
| retainRatio | 0.16(近期逐字保留) |
| maxTokens | 8192(摘要输出上限,**可被推理 token 耗尽**) |
| compactionRetries | 1(额外一次,共 2 次;但实测"第二次"相隔 25-29 分钟 ⇒ 是再次越线,非循环重试) |

**实测反推**(主样本):压缩前最后 ctx 791,759 → 压后第一轮 18,647;反推窗口 ≈989,699≈1M;压缩线 = 79.99%,与 0.8 精确吻合;**一次砍幅 97.6%**;**压缩比 ≈46:1**。

### 2.2 存活率(n=6 实压 + 差分)

| 类别 | 条数 | ①原话 | ②实体 | ③无 |
|---|---|---|---|---|
| user/message | 238 | **9 (3.8%)** | 77 (32.4%) | 152 (63.9%) |
| assistant/message | 335 | **0 (0.0%)** | **170 (50.7%)** | 165 (49.3%) |
| reasoning | 389 | **0 (0.0%)** | 179 (46.0%) | 210 (54.0%) |
| tool/result | 175 | 0 (0.6%) | 1 (0.6%) | 174 (99.4%) |

**两条关键读数**:

1. **assistant 与 reasoning 的原话存活 = 0.0%**——压缩指令写着 `Capture user feedback and explicit instructions faithfully`,**只点名保护用户的话**;agent 自己说过的话,摘要里一个字不留。
2. **assistant 实体存活反而最高(50.7%)**——摘要保下的"语言"是 **agent 视角的语言**(术语/路径/参数名)。⇒ 摘要天然偏袒"结论+名词",系统性丢"过程+为什么"。

### 2.3 磨损的真实构成(定性,来自第三层)

磨掉的主要**不是内容**(原文在盘上),是两样补不回来的:

- **等级**:摘要里引号身兼三义 ⇒ 读的人会把 **agent 的推测当用户的话用**;
- **"当时为什么这么判"**:原文只有"我写了什么";当时没写下来的理由,事后补的一定"长得很像,但不真"。

### 2.4 压缩失败的形态(1+1 样本,不能混)

| 会话 | 表现 | 成因 |
|---|---|---|
| 样本A | `DeepSeek request aborted by caller` | **人为打断**(不是后端错) |
| 样本B | `summarization truncated at the token cap` | **自然失败**:8192 被推理 token 吃光,摘要没写完(官方文档自认此条) |

⇒ 成因不同的两例不能合并成"压缩失败规律";成功后恢复极快(压缩结束 11 秒出正文,工具双通)。

## 三、复现

```powershell
node scripts/survival.mjs <session.jsonl.zstd> [--list] [--max N]
# 会话文件:C:\Users\<user>\.dsh\sessions\--D-<工作区>--\<session-id>\session.jsonl.zstd
```

**有效性边界**:一切按当时的 n 与口径使用。压缩器配方若升级,数字需重测;本报告对应 DSH 0.1.1-rc.2 / dsh-compaction-basic(thresholdRatio 0.8 · retainRatio 0.16 · maxTokens 8192)。
