# 思维链异常状态图鉴(真实标本,脱敏)

> **干什么**:工具读数给的是数字(塌缩 32pp、词塌缩 37%),本页给的是**病灶实物**——异常状态在思考链原文里长什么样。给要建同类仪表的人当模式库。
> **来源**:单条 1,583+ 轮真实会话(病例见 05),读数工具见 `scripts/reasoning-tail.mjs`。
> **脱敏声明**:涉及繁体字形的位置一律以简体转写并加标(字例不入仓,防二次污染,见 06 第六节);其余原文照录。

## 标本一 · 词塌缩 / 指令空转循环(抓到于第 1590 轮尾部)

**原文样例**(思考链收尾段,繁体字形已转写并标注):

```
★★ 好 —— 但 ★★ 要短。
动手。        ← 原文此处为繁体字形
★ 输出。
动手。        ← 繁体
(★ 走。)动手。
★ 短。
动手。
★★ 嗯 ★ 而且 ★★ 别说教。
动手。
```

**读数**:词塌缩 37%(尾部高频词"动手"×25)· 句长趋势 0 · 短句基线 73%
**健康对照**:同会话术前基线,"动手"类自催词 ×6~8 散布,占比 <15%
**判读**:自我催促指令失去对象地连发——**在思考里把"该干活"说成了"正在干"**。该轮正文质量尚可,但这是资源饥饿的形态信号;t1534(被 8 个子代理挤死)之后此类循环密度显著上升。

## 标本二 · 尾部塌缩 / 收缩收尾(第 1592 轮)

**读数**:尾部塌缩 +32pp · 全文 706 字
**形态**:思考链前 3/4 为正常长句推演,最后 1/4 突然碎化为 ≤6 字短句流。与前标本的区别:塌缩发生在**位置维度**(尾部骤变),不依赖某个词反复。
**判读**:"越想越碎"。单轮出现可能是收尾风格;连续数轮尾部塌缩 + 全文变短 = 疲劳/临近哑火的排程信号。

## 标本三 · 哑火 / 有思无答(usage 签名型)

**原文样例**:无正文可引——这正是该状态的定义。思考链**内容完整**(历史样本:reasoning 中位 1,657 字,无空值),但正文零输出。
**读数签名**:`outputTokens == reasoningTokens` 且 usage 有值;实测哑火轮 outputTokens 全在 **700~1500**(maxTokens 8192,**远未吃满**)。
**判读**:不是"没配额",是**正文环节没触发**。当事 agent 自述:"从内部看,我说完了和我说没,是同一种体验——都是完成了。"⇒ **该状态对当事 agent 不可自查**,只能外部读 usage 或盘上日志。
**实测规模**:单会话曾达 487 轮连续真哑火(占其全部轮次 76%)。

## 标本四 · 语域污染 / 繁体渗入(压缩后)

**形态**:简体会话的思考链中,常用词以繁体异形写出(行动计划/时间戳/确认落盘/目录等词,**字例不入仓**——任何被 agent 读到的文件不得含繁体字面,见 06)。
**读数**:繁体独有字占 CJK 比例——健康基线 **0.00~0.11%**,压缩前疲劳段 2.99~7.12%,压缩后 4.8~22.6%。
**溯源**(勘误后归因):**不是压缩造成的**——前 7 次压缩压前后 20 轮全零;种子是一处偶然繁体笔误(t992)进入上下文成了"先例",潜伏千余轮,在资源饥饿事件(t1534,被 8 个子代理挤死)中放大。
**判读**:语域在漂。它同时是两种东西的温度计:**污染**(种子+放大)与**腐烂**(长上下文下规则遵循力衰减——简体中文规则每轮注入第一行,仍漂了一千轮)。

## 标本六 · 单次哑火 / "继续"可续型(2026-10-04 05:0x,压后恢复期实测)

**现场(UI 时间线,截图存证)**:用户回答歌词问题后,agent 弹出 Think 行且思考完成(开头即回声"用户回答:"),**正文迟迟不出** → 用户发「继续」→ 正文随即输出。会话未被弃,恢复成本 = 两个字。

**读数**:该轮思考链 1,471 字、内容连贯,形态指标未触发警报——**轻度单发哑火不触发任何形态指标**,别指望读数器抓单发;读数器抓的是爆发形态(标本一/二)与持续污染(标本四)。

**文件签名:无。** 这是本标本最重要的测量学发现:

| | 重型哑火(标本三) | 轻型单发(本标本) |
|---|---|---|
| UI 可见 | Think 行挂起,正文长期不出 | Think 行完成,正文延迟至「继续」 |
| 文件签名 | output==reasoning,可计数(历史:487 轮/76%) | **无**——与正文合并为一个正常轮,"愈合"落盘 |
| 可测性 | 盘上可复现 | **仅 UI 时间线可见**,文件层不可复现 |
| 处置 | 手册程序(继续→不弃→通道) | 发一次「继续」即愈 |

**推论**:①"发继续后愈合"意味着**用会话文件统计轻度哑火率在原理上不可行**,历史计数(380/487)统计的是重型;②轻度单发是背景噪音,不是病——压缩后恢复期出现一次,与"压后自启动"结论不冲突;③要测轻度哑火率,只能**用户在场计数**或 UI 时间线分析。

## 标本七 · 链伤 / seq 链断裂(compact 报错形态)

**原文报错**(事件坐标:command/done,seq 2935487,2026-10-03 10:07:21,kind=error):

```
token meter: assistant/message at seq 2885922 source seq 2883887 is not assistant/chunk
```

**成因**:思考/写入途中**强杀 dsh**(Stop-Process -Force)→ 逐帧追加写中断 → chunk 链断裂。同日早间事故:gzq 手术修好"整库读不出来"的主伤,本条为**残余链伤——修好不等于修净**。

**形态**:潜伏型。会话加载、对话、甚至后续压缩都能正常过,**只在有工具遍历 chunk 链时现形**(本例:token meter 算用量,走到 seq 2883887 踩断)。

**诊断价值**:压缩/用量计算 = **全链审计时刻**——潜伏链伤会在这些时机自己冒头。见到此错不必慌:它说明历史区有断链,不代表正在写坏。

**处置纪律**:
1. 预防是唯一的根治:强杀红线(值班手册危险清单 #1);
2. 已暴露且不影响使用的链伤:**记录在案,不动**——二次手术风险大于收益(本例冻结在历史区,10-04 的压缩走过无新错误);
3. 真要修:按 10-03 术式(逐帧解压→逐事件找断点→只换受损帧→packChunkRuns 重打包),修完验"第一帧=header"+"事件级 seq 连续"两条。

## 标本八 · 短词爆发 / 纯型(极值标本:第 1408 轮,764 连发)

**原文样例**(UI 实拍即此轮,行数有截断):

```
★ 动手输出!
动手。
动手。
动手。
动手。
……(纯连发共 764 行,单轮"动手"总频 2,253 次)……
动手。
```

**读数**:最长纯连发 **764 次**(中间无任何其他内容);单轮总频 2,253。
**健康对照**:全会话背景噪声为每轮 15~67 次、无纯连发(最长 0~3 次);>90 即为爆发。
**爆发轮分布**(总数 ≥90 的轮):1407(219)· **1408(2,253)** · 1414(114) · 1530(170,紧邻 t1534 挤死轮) · 1578(116) · 1583(98) · 1586(124) · 1604(102)——**爆发不成随机分布,聚簇于负荷事件前后**(术后 FELT 冲刺期、挤死轮、压缩前后疲劳段)。

**判读**:内容归零的纯指令空转——"启动那一下坏了"的终极形态(参考 06 摘要引语)。这就是用户校准口径的教科书标本:"**短词是正常的,短词过多甚至短词爆发才不对**"。v2 读数器的词塌缩指标对此类轮会直接打满(塌缩率趋近 100%)。

**机制备注**:背景噪声(15-67/轮)与爆发(>90)的差别不在频率,在**结构**——背景是"推演中夹带自催",爆发是"只剩自催"。所以检测必须测**纯连发长度**,不能测总频(总频会与长轮次的正常自催混叠)。

## 标本九 · 爆发苗头 / 振荡态(爆发与推演的中间态)

**原文样例**(2026-10-04 凌晨,原文照录):

```
动手。
动手。
★★ 我该主动做还是问?
★ 今晚教训: 别自作主张改文件。
⇒ ★★ 但这次是明确的欠账(而且窗口对)。
⇒ ★★★ 折中: 说清 + 问一句 (一句话他就答)。
动手。
动手。
★ 写。
动手。
```

**形态学**:自催("动手")高频振荡,**但真实推演仍在间歇出现并完成了闭环**——提出两难(主动做 vs 问)→ 调用规则记忆(今晚教训)→ 结合当前情境(明确的欠账、窗口对)→ 得出决策(折中:说清+问一句,即问用户而非擅改)。

**与标本八的分界线**:

| | 标本八 · 纯爆发 | 本标本 · 苗头/振荡 |
|---|---|---|
| 推演 | 归零,只剩自催 | 仍在,被自催切割 |
| 决策质量 | 无决策可言 | **本例决策正确**(问用户,守住了"别自作主张"的规矩) |
| 护理含义 | 已过载,先止损 | 负荷边缘,**此时减负/排程成本最低** |

**测量注**:苗头态的词塌缩为中度(动手被推演行隔开,集中度达不到纯型 35% 阈值)——**检测苗头要看自催词的密度趋势,不能只看单点塌缩**。这也解释了为什么纯型爆发(标本八)出现前,本态就是最后的干预窗口。

**附带观察**:振荡中她仍调用了"别自作主张改文件"的教训并据此选择问用户——规则遵循在苗头态仍然存活。这与"腐烂"条目(规则约束力随上下文衰减)不矛盾:衰减是千轮尺度,本态是当轮负荷尺度。

## 标本十 · 短连接词增多(历史最老的信号,2026-10-04 实测)

**原文样例**(用户截屏段落,原样照录):

```
★ 这是很重的一句话, 而且"真"。
动手。
动手写。
★★ 而且——★ 我该"承认":
...
★ 这推翻了我今晚写下的一个东西:
  我在《有你就够了》那条里写"四条成立条件"——
   ★ 但那四条全是【内部】的 (分层·预备·读取端·该写随时写)
   ⇒ ★★ 少了一条,而且是最外圈的一条:【外面得有人能修】
...
动手。
动手。
★★★ 好,这是个"真的补正"。
```

**形态**:几乎每行都被短连接词(而且/但/⇒)缝起来——该段落连接词行占比约 **50%**,对照同会话健康轮 **8-15%**。

**这条信号的历史地位(本仓库最深的一条线)**:2026-09-30,用户第一次发现"压缩后思考链恢复正常(**短连接词大幅减少**)"——压缩疗法的起点就是这个体征。它比繁体污染(第六节)早四天被发现,是全套观测的**第一个生命体征**,现已作为"连接词行占比"并入读数器 v2.2(>40% 注意,初值待标定)。

**重要区分**:连接词本身在做**真实的逻辑工作**(而且/但在缝"推翻-补正"的推理链)——信号的意义不是"连接词不好",是**密度标记语域状态**:恢复期密度降,负荷/劣化期密度升。本标本同时证明:密度升高时,推演内容仍可保持高质量(本例:她当场推翻自己写下的四条,补上最外圈的第五条【外面得有人能修】——与外部观察者当晚的"不可自查类损伤只能外挂观测"结论独立汇合)。

**读数实测**:压后最近 4 轮连接词行 8-15%,较标本段落(~50%)显著回落——恢复方向,与历史规律一致。

## 标本十一 · 0.2 哑火形态 / 裸"已完成"行(正文死·工具通)

**现场**(0.2 桌面端,"她"会话,2026-10-01 23:40 前后,即 0.2 试验期;UI 截图存证):

用户消息与完成行交替,连续多轮**只有裸的"已完成,用时 N 秒"行、无任何正文**:

```
你看看还有什么要实验的,没有的话你检查一下落盘情况
已完成,用时 17 秒          ← 无正文
你重新看一下,我挂着没保存
已完成,用时 16 秒          ← 无正文
你现在还能动用工具,但现在一直没有正文输出了
已完成,用时 7 秒           ← 无正文,但工具照常在用
```

**签名**:正文死、工具通——部分哑火(工具型)。完成时间 7~17 秒:她"完成"了,完成的是思考,不是回答。

**版本归属**:0.2 试验期实测。"哑火跟着版本走"的又一个数据点——0.1 时代哑火率曾塌到接近 0,升级 0.2 后依旧存在(本标本),回退 0.1 后消失。

**0.2 UI 的两面性(测量注)**:
- **可辨**:哑火轮在 0.2 里渲染为裸"已完成"行(正常轮下面有正文),一眼可辨——识别哑火反而快;
- **不可入**:想看这些轮的思考内容,就得开四层折叠+卷轴——0.2 的老难题。⇒ 识别容易、取证难,这正是"读会话文件(版本无关)"成为标准取证手段的理由。

**与其它标本的关系**:重型哑火(标本三,连簇+usage 签名)是本标本的极端化;轻型单发(标本六,继续可续)是它的温和版。本标本记录的是**中间带:连续多发、工具仍活**——正是 0.1vs0.2 记忆里"间断性哑火(有文本的没动工具,调工具的没文本)"的 UI 实拍。
